# 日本語市場でのSEO

英語圏の手順をそのまま適用すると外れる部分だけをまとめる。基本の手順は [../docs/](../docs/) にある。

事実の確認日は2026-08-17。

## 検索エンジンのシェア

Yahoo! JAPANは2010年に自社の検索技術からGoogleの検索エンジンに切り替えている。2024年5月の報道では契約が2年延長され、2027年3月までGoogleの検索技術を使うとされている（[Web担当者Forum](https://webtan.impress.co.jp/e/2024/05/17/47019/page/1)）。したがってランキングの対策先はGoogleに一本化してよい。

ただし検索結果の見せ方と周辺機能はYahoo! JAPAN独自なので、順位は同じでもクリック率は一致しない。Yahoo!経由の流入が多いサイトでは、順位ではなくクリック数で判断する。

Bingは国内シェアが小さい一方で、Windowsの既定検索であるため法人・自治体の職場端末からの割合が相対的に高くなる場合がある。BtoBや行政向けのサイトでは Bing Webmaster Tools も登録しておく。登録は無料で、作業は30分で終わる。

## 表記ゆれ

日本語には同じ語の書き方が複数ある。クエリ側の表記が分かれるので、ページ側で全部を拾おうとして本文を壊すことになりやすい。

| 種類 | 例 |
| --- | --- |
| 漢字とかなの選択 | 問い合わせ / お問合せ / お問合わせ |
| 送り仮名 | 申込 / 申し込み / 申込み |
| 長音記号 | サーバー / サーバ、ユーザー / ユーザ |
| 全角と半角 | ＡＩ / AI、１ / 1 |
| カタカナとアルファベット | クラウド / cloud |

対処は3つ。実際に検索されている表記をSearch Consoleのクエリで確認して、本文の主表記をそれに合わせる。表記を混ぜて詰め込まない。サイト内検索を持っているなら、そのログが最も正確な表記の証拠になる。

「表記ゆれ対策として全パターンを本文に入れる」は [13-antipatterns](../docs/13-antipatterns.md) のキーワード詰め込みと同じことなので、やらない。

## 単語の区切りがない

日本語の文には空白による語の区切りがない。英語の感覚で「タイトルにキーワードを含める」を考えると、意図しない語が切り出される場合がある。

実務上の影響は限定的で、気にする価値があるのは固有名詞と造語だけ。新しいサービス名を作るときに、既存の一般語と衝突する切り方になっていないかを検索して確かめておく。

## title と description の長さ

日本語1文字は英語の1文字より幅が広いので、英語の目安（title 60文字程度）はそのまま使えない。全角30文字前後で切られることが多い。ただし表示は文字数ではなくピクセル幅で決まり、デバイスによっても変わるので、正確な閾値を追うより、重要な語を先頭に置くほうが確実に効く。

会社名を先頭に置くパターンは、全ページの先頭が同じ文字列になるため損をする。ページ固有の部分を先に書く。

## 日本語のWebフォントとCWV

日本語フォントは収録字数が多く、サブセット化していないと1ファイルで数MBになる。LCPとCLSの両方に直接効くので、日本語サイトの表示速度の問題は、多くの場合ここが原因になる。

確認する順番は、フォントファイルのサイズ、`font-display` の設定、サブセット化の有無、そしてそもそもWebフォントが必要かどうか。システムフォントで足りる本文にWebフォントを当てているサイトは多い。

## 自治体・BtoBの検索行動

行政向け、法人向けのサイトでは、検索する人が担当者であり、購買の決定者ではないことが多い。担当者は上司に説明するための材料を探している。

そのため、価格、導入実績、対応範囲、必要な体制、他社との違いが1ページに書かれていることの価値が、一般消費者向けサイトより高くなる。これは [11-ai-search-visibility](../docs/11-ai-search-visibility.md) で書いた「引用されやすい書き方」と同じ方向を向いている。

クエリの形も違う。「〇〇市 補助金 申請」「勤怠管理システム 自治体 導入事例」のように、地名や業種と組み合わせた具体的な語になる。検索ボリュームは小さく、1件あたりの価値は大きい。ボリューム順に並べると全部切り捨てることになるので、[06-phase2-prioritization](../docs/06-phase2-prioritization.md) の上書き条件を使って手で拾い上げる。

「〇〇とは」で調べる段階の人と、製品名で調べる段階の人は別のページで受ける。1ページで両方を狙うと、どちらにも中途半端になる。

## 日本語のURL

日本語を含むURLはパーセントエンコードされる。共有時に長大な文字列になり、外部サイトにリンクを貼ってもらうときの摩擦になる。ローマ字か英語のスラッグを使うほうが扱いやすい。

すでに日本語URLで運用していて順位もついているなら、変更する価値は小さい。移行のリスクのほうが大きい。

## 多言語サイト

日英を持つサイトでは `hreflang` を `ja` と `en` で相互参照させ、自己参照も入れる。地域を分ける必要がなければ `ja-JP` ではなく `ja` でよい。

クローラは一般に en-US 相当でアクセスする。ブラウザの言語設定を見てJavaScriptでリダイレクトする実装は、日本語ページに到達させられないことがある。詳細は [10-javascript-sites](../docs/10-javascript-sites.md)。日本語で売っている事業でこれが起きると、影響は英語ページの比ではない。

## 検索ボリュームのデータ

日本語クエリのボリュームはツールによって差が大きい。特に長いクエリでは、ツール側が「データなし」を返すことと、実際に検索されていないことが区別できない。

Search Consoleのクエリデータは、そのサイトが実際に表示された分だけとはいえ、日本語では推定値より信頼できる。まず自分のデータを見てから外部の推定を使う。
